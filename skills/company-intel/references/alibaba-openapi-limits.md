# 阿里国际站 OpenAPI 能力边界

## 开放的 API（2026 年现状）

### 商品管理（Products）— 最丰富
- 发品/更新/删除/批量操作
- 图片银行（上传/管理）
- 类目/属性/schema
- 草稿管理、产品评分

### 订单与交易（Trade）
- 订单列表/详情/资金/物流
- 创建/修改交易订单
- 收货地址管理
- ERP 同步接口（销售订单/账单/发货）

### 物流
- 运费模板
- 海外准入检查

## 不开放的 API（核心缺口）

| 能力 | 状态 | 原因 |
|------|------|------|
| 买家询盘消息读取 | ❌ 不开放 | 阿里把询盘留在平台内 |
| 即时通讯/聊天 | ❌ 不开放 | 同上 |
| 客户信息管理 | ❌ 不开放 | 客户数据是平台资产 |
| 报价发送 | ❌ 不开放 | 交易闭环内完成 |

## 关键发现

**阿里的护城河 = 询盘和沟通数据不开放。**

Accio Work 能操作国际站后台，因为它是阿里亲儿子，走的是内部接口，不是 OpenAPI。第三方 ISV 和 SSA 系统无法通过公开 API 获取询盘消息。

## 对 SSA 的战略意义

- 阿里 OpenAPI 面向的是 **ERP 集成场景**（商品 + 订单履约）
- 它不覆盖 **客户沟通场景**（询盘 + 报价 + 谈判）
- SSA 做的是询盘到成交的链路，和阿里的 API 不在同一维度
- 真正有价值的还是把现有的 **独立站 + OKKI 链路** 做到极致
